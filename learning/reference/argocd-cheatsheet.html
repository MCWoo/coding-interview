Argo CD cheat sheet

Quick reference — see Lesson 1 for the full explanation.

Scope, one line

Argo CD reconciles Kubernetes manifests against a Git repo. It has no model of cloud infrastructure (VMs, networking, IAM) — that's Terraform's job, finished before Argo CD ever acts.

Core object

Application (a CRD) = a source (Git repo + path/branch, or a Helm/Kustomize reference) + a destination (target cluster + namespace).

Three mechanics

Sync Reconcile live state to match Git. Manual or automated.
Self-heal Off by default. Reverts manual kubectl drift back to Git.
Prune Off by default (safety). Deletes live resources removed from Git.

One-sentence interview answer

"Argo CD picks up once there's a cluster and manifests to reconcile — everything before that (provisioning the cluster, networking, IAM) is still Terraform's job."

Worth knowing for follow-ups

  • App-of-Apps — one root Application managing many child Applications, for scaling GitOps across many services/teams.
  • Sync waves / hooks — ordering control within a single sync (e.g. run a DB migration Job before the app Deployment rolls out).
  • Image Updater — a separate Argo CD component that can auto-bump image tags in Git when a new image is published, closing the loop without a human editing the manifest.
